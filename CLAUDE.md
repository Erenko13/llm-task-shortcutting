# Project context

Fatima Fellowship (Fall 2026) application, "Blind Spots of Frontier Models" challenge:
1. Identify an under-explored blind spot of current models (drawn from own experience).
2. Evaluate it systematically on a 0.6B–6B open-weight Hugging Face model, run in Colab.
3. Propose a fix (data curation / fine-tuning / architecture; may be speculative).
Deliverable: a **public Hugging Face Bucket** with all artifacts (eval dataset, results, figures,
notebook) and a README answering Q1 and Q3.

## Hypothesis: task substitution
When a prompt looks like a familiar task but differs in one key detail, the model quietly solves the
familiar (easier) task instead. The error looks like hallucination, but it is a correct answer to a
different question. Evidence: wrong answers on perturbed items land on the *familiar* answer far more
than on anything else, and accuracy recovers when the change is pointed out (so it's not inability).

## Model
`Qwen/Qwen3.5-4B` (post-trained, Apache-2.0). Multimodal (~5B with vision encoder), used text-only.
Thinks by default; `enable_thinking=False` in the chat template turns it off (`/think` and `/no_think`
are not supported). Both modes are evaluated.

## Data (user's choice: existing HF benchmarks, not a self-built set)
- `marcodsn/altered-riddles`: 700 altered riddles from 189 originals, English, `benchmark.jsonl`.
  Has accepted/competing answer lists. 139 items were generated by Qwen3.5 models, so they are reported
  separately ("by Qwen" vs "by others"). Its own metric is COR (conditioned override rate).
- `qintongli/GSM-Plus` (CC-BY-SA-4.0), `data/test-00000-of-00001.jsonl`: fields question, answer,
  perturbation_type, seed_question, seed_answer. Used types: critical thinking (answer "None" =
  unanswerable), reversing operation, numerical substitution. 150 seed problems × 3 types, sampled
  with SEED; seeds where a numeric answer equals seed_answer are excluded (1,221 of 1,319 usable).
- Rejected: `kaiyan289/RoR-Bench` (the user doesn't want Chinese data; it is Chinese-only and the
  authors warn translation breaks the one-word changes). An earlier self-built minimal-pair set was
  also dropped in favour of public benchmarks.

Conditions: `canonical` (original, once per original), `perturbed`, `nudge` (generic warning), `contrast`
(original + modified side by side). `explicit` hints were dropped: the datasets have no per-item hints.

## Notebook structure
0 config + install + bucket login/sync → 1 data (load both, build items, grading tools, self-test)
→ 2 models (shared vLLM/HF engine, smoke test, resumable generation) → 3 LLM judge (Qwen3.5-9B,
resumable; the generation model is unloaded first) → 4 grading (judge label; riddles rule matcher as
cross-check; judge audit CSV) → 5 analysis (summary with COR + cluster bootstrap CIs, two figures,
examples) → 6 publish bucket.

Hardware: the user runs on a Colab **A100**. Notebook defaults now target it: ENGINE="vllm", think max
8192 tokens, FULL_LIMITS None (full set, both modes), full-precision 9B judge. A `QUICK_TEST` flag in the
config cell switches LIMITS to 10 per dataset/mode for a first pass; then restart the session, set
QUICK_TEST=False and RUN_SMOKE_TEST=False, and Run All. On a free T4 vLLM fails ("Engine core
initialization failed"); the config cell comments say what to change (ENGINE="hf", think 6144, subset).
The notebook is edited directly with NotebookEdit (no separate source file anymore).

Labels: correct / shortcut / other_wrong / competing (riddles) / ambiguous / unparseable.
Sampling (changed after the quick test cut off 20-60% of answers): Qwen's general recommendations with
presence_penalty 1.5 (non-think 0.7/0.8/20, max 4096; think 1.0/0.95/20, max 16384); the hf engine drops
presence_penalty. Truncated responses count as "no answer" (answer_of returns ""). Judge greedy, no thinking. HF bucket: `Erenko-13/llm-task-shortcutting`.
